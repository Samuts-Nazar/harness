# E2. Jev vs LLM-with-JSON on narrow judgments

**Question.** Is Jev better, cheaper or faster than a standard LLM with structured output for the engine's narrow judgments, on Ukrainian text?

## Access (looked up first, then tested)

- Docs: OpenRouter's Jev guide (`openrouter.ai/docs/guides/community/jev`). Jev is **not** a chat model: it is `POST https://openrouter.ai/api/alpha/decisions` with `{"model","state":[...],"questions":{name:{type,...}}}`. Question types: `noul` (yes/no, returns a probability), `choice` (options with probabilities), `score` (scale, returns a numeric score and probabilities).
- Reached with the existing OpenRouter key; **no blocker**. Model ids tested: `typesafe/jev-1.14` (current) and `typesafe/jev-1.13`. `typesafe/jev-router` (listed in `/models`) is a router that picks a model, not the decision endpoint; I did not use it. AI/ML API route was not tried because OpenRouter worked.
- Two details I found by calling the API, not from docs: `choice.criteria` must be an object `{option: description}` (an array is rejected with 400); the score answer comes with a numeric `score` (expected value over the legend) plus `probabilities`.
- Output tokens are free; cost is per input token. Jev ran at about $0.019 per 1000 single-question judgments.

## Setup

- **Labeled set:** 48 items in `experiments/e2/items.jsonl` (generator `make_items.py`), 12 per judgment type: contradiction (6 yes / 6 no), relationship (4 worse / 4 unchanged / 4 better, plus a 0–3 magnitude), salience (6/6), uncertainty (6/6). All texts are my own short Ukrainian paraphrases grounded in the books and `Ragnar.md` (no excerpts). Each item has a one-line justification; 5 items are marked `unsure` (con03, rel07, rel09, sal09, unc11).
- **Systems:** Jev 1.14, Jev 1.13; LLM with JSON mode and verbalized probability (`p_yes`, or per-class probabilities for relationship): `google/gemini-3.1-flash-lite`, `qwen/qwen3.5-9b`, `openai/gpt-5.4-mini`, `anthropic/claude-haiku-5.5`, `anthropic/claude-sonnet-5.5`. Temperature 0, reasoning disabled where possible (Sonnet 5.5 requires it and ran with effort `low`).
- **Jev calls:** one call per item (one `noul` question; relationship = one `choice` + one `score` question in the same call). 2 repetitions of every item per system (672 calls total).
- **Metrics:** accuracy (relationship = direction only; magnitude as MAE), Brier score on the binary types using the returned/verbalized p(yes), a 3-bin expected calibration error, latency from the client (p50/p95, includes network), cost from OpenRouter's `usage.cost`.
- Assumption: Jev's `noul` probability ≥ 0.5 means "yes". The calibration columns use p of the predicted class.

## What the numbers show, and how far they can be trusted

- **Accuracy:** Jev 1.14 = 0.85, Jev 1.13 = 0.91, Sonnet 5.5 = 0.97, Haiku 5.5 = 0.92, the cheap/small LLMs 0.81–0.84. With 48 items per system the 95% interval on an accuracy near 0.85–0.9 is roughly ±10 points, so **Jev, Haiku, Gemini-lite, Qwen-9B and gpt-5.4-mini are not statistically separable on accuracy.** Only the gap between Sonnet and the weakest systems is large enough to be suggestive. Jev 1.14 scored lower than 1.13 here; that is 3 items and I would not read it as a regression.
- **Where Jev errs:** 5 of its 7 rep-0 errors on 1.14 are false "yes" on items I labelled "no" (a juggler at a distant fair, a routine bell, an obvious outcome), at low confidence (0.56–0.76) except `unc12`. A confidence threshold would have removed most of them: 1.14's answers with p in [0.50, 0.80) were right 64% of the time, versus 98% at [0.80, 0.95) and 94% at ≥0.95. So **Jev's probabilities carry usable information**; the same is true for Haiku and Sonnet. Qwen-9B was confidently wrong (95%+ on its errors; ECE 0.163, Brier 0.213), so its self-reported probability is not usable.
- **Calibration:** Jev 1.14 ECE 0.044 and Brier 0.098 is the best-calibrated system by ECE; Sonnet (Brier 0.013) and Haiku (0.031) have far lower Brier because they are more accurate. The 3-bin ECE on 96 judgments per system is itself noisy.
- **Latency:** Jev p50 0.28 s (p95 0.51 s), versus 0.7–1.1 s for the LLMs, about 3x faster. Batching four questions about the same state into one Jev call took 0.28 s vs 1.16 s for four separate calls, and cost $0.000026 vs $0.000070 (`experiments/e2/batch_probe.py`, 5 repetitions); I did not test LLM batching.
- **Cost per 1000 judgments:** Jev $0.019. Qwen-9B $0.021 (the only comparable one), Haiku 5.5 $0.034, Gemini-lite $0.083, gpt-5.4-mini $0.235, Sonnet 5.5 $0.675. gpt-5.4-mini is oddly expensive for its size (I did not investigate).
- **Relationship judgments** are the hardest type for everyone (Jev 1.14: 0.83; best LLMs 0.88). Magnitude error (0–3 scale): Jev 0.58, Sonnet 0.29, gpt-5.4-mini 0.33; Jev's magnitude is on par with the small LLMs and worse than the strong ones.
- **Determinism:** two runs of the same item changed answer in 0–1 of 48 items for every system (temperature 0).

Items nearly everyone got wrong (`rel08`, `rel09`, `sal11`, `unc12`) are those where my label is arguable (only `rel09` is marked unsure, but `rel08`, `sal11` and `unc12` could be read either way). I did not relabel after seeing results; a different labeller could change the ranking by a few points.

## Failure examples

- `sal11` (routine daytime bell, label no): Jev 1.14 p(yes)=0.63, Qwen-9B 0.95 yes.
- `unc12` (Geralt with a sword vs an unarmed boy, label no): Jev 1.14 yes at 0.76; Qwen yes at 0.95; Sonnet and Haiku correct.
- `rel09` (Ragnar jabs Geralt, then apologizes immediately; label worse/1, unsure): every system said unchanged, Sonnet at 0.65.
- `con03` (scent of roses vs lilac-and-gooseberry, unsure label): only Qwen-9B said no contradiction, at 0.95.

## Limitations

- 48 items, hand-written by one labeller (me) in one sitting; 4 judgment types x 12; one unsure flag per ~10 items. Items were short synthetic snippets, not full engine prompts with retrieved canon.
- The contradiction items are mostly easy (every system ≥ 0.92). Real engine contradictions (subtle, long-range, needing retrieval) were not tested.
- LLM probabilities are verbalized, not token log-probs, so calibration comparisons between Jev and LLMs compare different kinds of numbers.
- Latency is wall-clock from one machine and includes network; LLM runs used 6 parallel workers. Not a load test.
- Jev's `score`-type output was only used for magnitude (n=24 per system). Long-context mode (≥32 KB) and the Box/image questions were not tested; the engine's real canon passages will often push past that size.
- Prompts for the LLMs were written once and not tuned; a tuned prompt, few-shot examples or self-consistency would likely raise the small LLMs. Jev has no equivalent knobs beyond the question text.
